# expert-bootstrap

> Bootstrap a project-local council of generated domain experts for Claude Code.

`expert-bootstrap` is a Claude Code skill that turns "I want to start a project" into a ready-to-use expert team. It does NOT ship pre-baked experts — instead, two meta-agents (`prompt-engineer` and `project-manager`) **generate a roster tailored to your project** and write them to `./.claude/agents/` so Claude Code can natively dispatch them as subagents.

## What you get after running it

```
your-project/
├── brief/
│   └── goal.md                       ← canonical project goal (single source of truth)
├── .claude/agents/
│   ├── react-expert.md               ← generated by project-manager + prompt-engineer
│   ├── api-architect.md              ← (your roster will differ — depends on the project)
│   ├── security-auditor.md
│   └── ...
└── CLAUDE.md                         ← council convening rules + roster index
```

Each expert is a real Claude Code subagent — invocable via `Agent(subagent_type="<name>")` or auto-triggered by description matching.

## Install

### Via Claude Code plugin marketplace (recommended)

```bash
# In Claude Code:
/plugin marketplace add SEAMAN9000/expert-bootstrap
/plugin install expert-bootstrap@SEAMAN9000
```

### Manual install

```bash
git clone https://github.com/SEAMAN9000/expert-bootstrap.git
cd expert-bootstrap

# Copy into your global Claude Code config:
cp -r skills/expert-bootstrap ~/.claude/skills/
cp agents/*.md                ~/.claude/agents/
cp commands/expert-bootstrap.md ~/.claude/commands/
```

## Use

In any project directory:

```
/expert-bootstrap
```

Or in plain language (must mention "expert team / council / 专家组"):
- 「组建专家组」「初始化专家组」「成立专家委员会」
- "set up the experts", "convene the expert council"

Generic project-start phrases (「启动项目」/ "start a new project") will **not** trigger this — they fall through to `superpowers:brainstorming`. This is intentional: not every project needs a council.

## How it works (5 steps)

1. **Project discovery** — three states: A) you state a clear goal, B) you point at fragments/notes, C) you have nothing → 5 interactive questions, one at a time
2. **Refine the brief** — `prompt-engineer` tightens the goal statement → written to `brief/goal.md`
3. **Design the roster** — `project-manager` reads `brief/goal.md`, returns a YAML roster of 3–7 experts (you confirm)
4. **Refine each expert** — `prompt-engineer` runs in parallel for every expert, producing a production-grade system prompt
5. **Write to disk** — each expert lands in `./.claude/agents/<name>.md`; `CLAUDE.md` gets a council section

The bootstrap is the deliverable. The skill stops; it does not start implementing.

## Design principles

- **Zero global pollution** — domain experts live in project-local `./.claude/agents/`, not your global `~/.claude/agents/`. Leave the project, they're invisible.
- **Two meta-agents, generated specialists** — only `prompt-engineer` and `project-manager` are persistent (in `~/.claude/agents/`). Domain experts are project-bound and regenerated when you re-run.
- **Smallest viable council** — `project-manager` defaults to 3–4 experts, with one skeptic seat reserved when council ≥ 4.
- **No hand-edits to generated files** — drift discipline is documented in the project `CLAUDE.md`. Re-run the meta-agent for changes.
- **Plays nice with `superpowers`** — supersedes `superpowers:brainstorming` only when the user explicitly asks for a council. Feature-level brainstorming and downstream `writing-plans` / `executing-plans` flow normally.

## Compatibility

- **Claude Code** — primary target (uses native `Agent(subagent_type=...)` dispatching)
- **Other agents (Codex, Gemini CLI, OpenCode)** — should work for the file generation steps, but native subagent dispatching of generated experts is Claude Code-specific
